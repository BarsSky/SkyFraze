# Общий чат проекта и Нестор в нём (0.95.0)

Статус: **сделано в 0.95.0**. Документ отвечает на вопрос «как участники обсуждают проект и
зачем в чате бот», и честно перечисляет, чего в этой версии нет.

## 1. Зачем отдельный чат, если есть замечания к кадру

Замечание (0.68–0.90) привязано к **фрагменту текста** и живёт в блоке кадра: «здесь герой не мог
знать про маяк». Это правильный инструмент для правки конкретного места, но неправильный для
«обсудить идею, спросить коллегу, позвать Нестора на разбор»:

* замечание без кадра не поставить, а разговор часто начинается до того, как есть кадр;
* замечания разбросаны по кадрам — общей картины «о чём мы говорим в проекте» не видно;
* читатель проекта (viewer) не участвует в обсуждении, хотя именно его мнение часто и нужно.

Поэтому чат — **одна лента на проект**, рядом с окном помощника.

## 2. Как это устроено

### 2.1. Одно окно, две вкладки

Плавающая кнопка (она же кнопка помощника) открывает окно с двумя вкладками:

| Вкладка | Что внутри | Кто видит ответ |
|---|---|---|
| **Помощник** | прежний ИИ-помощник: вопросы, правки по подтверждению, карточки | только спросивший (его беседа) |
| **Чат проекта** | лента сообщений проекта, ссылки на кадры и фразы, кнопка «спросить бота» | все участники |

Почему одно окно: кнопка одна и узнаваемая, а человек либо спрашивает Нестора, либо пишет
людям. Второе плавающее окно поверх первого — лишний слой и лишняя кнопка. Панель помощника при
переключении **не размонтируется**: история, выбранная модель и набранный вопрос остаются.

### 2.2. Ссылка на элемент текста

Сообщение может нести ссылку на **кадр** и, необязательно, на **точную фразу** из него:

* кадр обязан принадлежать этому проекту (чужой id — отказ 404, а не «ссылка в никуда»);
* фраза проверяется по тексту или заголовку кадра — если её там нет, сервер отказывает с
  объяснением, а не сохраняет пустую ссылку;
* клик по ссылке в чате открывает кадр в редакторах (страница переключает вкладку и передаёт
  просьбу панели).

Якорей CRDT (`Y.RelativePosition`) у сообщений чата нет намеренно: чат — не замечание к
фрагменту, и «показать в тексте» здесь делает клиент по цитате. Это переживает правки текста без
специальной поддержки — цена: при двух одинаковых фразах в кадре подсветки нет, открывается кадр
и видна сама цитата в ссылке.

### 2.3. Нестор в чате

В composer есть кнопка «спросить бота»: сообщение уходит и людям, и Нестору, ответ приходит
**отдельным сообщением** с подписью бота (`kind = 'bot'`).

Ключевое решение: **ответ в чат не меняет проект.**

* возможности урезаны до чтения (`Capabilities.ReadOnly`): модели не выдаются инструменты
  создания/правки, а в правилах сказано «ответь текстом, ничего не создавай»;
* запрет проверяется и **при исполнении** — модель присылает вызов инструмента текстовым блоком
  (`skyfraze-tools`), и это минует список инструментов. Живая проверка поймала ровно это: бот,
  которому запретили менять проект, создал главу и отчитался. Теперь `execute` отклоняет
  «меняющий» инструмент с объяснением, а разрешены только чтение: `list_events`, `read_event`,
  `read_comments`, `list_entities`, `read_entity`;
* вопрос к модели собирается с контекстом: кадр, цитата, текст кадра (до 1500 знаков), автор
  вопроса. Без этого бот отвечает «вообще», и его ответ бесполезен;
* если Нестор выключен на стенде или в проекте, сообщение участника **сохраняется**, а рядом
  появляется причина, почему ответа нет. Терять вопрос нельзя.

Беседа на каждый вопрос своя: чат — разговор участников, и подмешивать в него историю окна
помощника значило бы отвечать то, что обсуждали в другом месте.

### 2.4. Реальное время

Опрос: вкладка спрашивает «что нового после последнего известного» раз в 4 секунды (закрытая —
раз в 8, только ради маркера). Отдельный WebSocket ради чата не заводим: в проекте уже есть
collaborативный канал для документа, и второй канал состояния — это второй набор гонок и
переподключений. Задержка в пару секунд для обсуждения незаметна.

Непрочитанное: личная отметка «последнее прочитанное» в `localStorage`, счётчик на вкладке чата и
на плавающей кнопке.

## 3. Хранение и API

### 3.1. Миграция `0038_project_chat`

```sql
create table project_chat_messages (
  id uuid primary key default gen_random_uuid(),
  project_id uuid not null references projects(id) on delete cascade,
  author_id uuid references users(id) on delete set null,
  author_name text not null,          -- подпись на момент сообщения (автор может быть удалён)
  kind text not null default 'user' check (kind in ('user','bot')),
  body text not null check (char_length(btrim(body)) between 1 and 4000),
  event_id uuid references events(id) on delete set null,  -- кадр-ссылка
  quote text not null default '',     -- точная фраза из кадра
  created_at timestamptz not null default now()
);
create index project_chat_messages_project_idx on project_chat_messages (project_id, created_at, id);
```

`on delete set null` у кадра — важно: удалили кадр, сообщение остаётся, ссылка исчезает. Терять
весь разговор из-за одного кадра нельзя.

### 3.2. Ручки (в под-дереве `/api/projects/{id}`)

| Метод | Путь | Права | Что делает |
|---|---|---|---|
| `GET` | `/chat/messages?after=<id>&limit=<n>` | viewer+ | сообщения по порядку; `after` — только новые; в ответе `bot: {name, available}` |
| `POST` | `/chat/messages` | viewer+ | `{body, event_id?, quote?, ask_bot?}`; ответ — `{message, reply?, note?}` |

Писать может и читатель: чат — разговор, а не правка текста. Менять проект он по-прежнему не
может.

## 4. Ограничения этой версии (честно)

* **Рассылки в реальном времени нет** — опрос (см. §2.4). Для «двое сидят и обсуждают» задержка
  до 4 секунд; для мгновенного чата понадобится канал, и это отдельная задача.
* **Нет реакций, ответов на сообщение (thread), редактирования и удаления** — только лента.
  «Ответить» заменяется цитатой в тексте, ссылка на кадр — отдельное поле.
* **Нет вложений в чате** — картинку показывают вложениями кадра; в чате можно дать ссылку на кадр.
* **Бот отвечает только по просьбе** (кнопка), не по «@Нестор» в тексте: упоминание в свободном
  тексте слишком легко срабатывает случайно. Порог «когда отвечать» — решение, а не догадка.
* **Бот не помнит предыдущие сообщения чата** — каждый вопрос отдельная беседа; контекст даётся
  ссылкой на кадр и цитатой. «Помни, что мы обсуждали выше» он не выполнит.
* **Уведомлений о новых сообщениях нет** (писем/колокольчика) — только маркер в окне.
