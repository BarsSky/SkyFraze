# Импорт и экспорт: формат папки с Markdown

Договор о формате: как проект выгружается в Markdown и zip и как папка с md
превращается обратно в проект. Замысел — один и тот же набор файлов читают и человек,
и внешние инструменты (git, редакторы, pandoc), и сам SkyFraze.

Общее предложение и порядок работ — в `docs/import-export-folders.md`. Этот файл —
точные правила; если правила и код разойдутся, прав код, и файл надо поправить.

## 1. Выгрузка

### 1.1. Одна лента: `GET /api/projects/{id}/export.md`

`Content-Type: text/markdown; charset=utf-8`, скачивается как
`<заголовок-проекта>.md` (имя — слаг от заголовка).

Структура:

```markdown
# Планета — АнуВаар
Описание проекта, если оно есть.

<!-- skyfraze: number=01 id=8f38… kind=event -->
## 01 Пролог. Представление.
Текст главы как есть (это уже Markdown: заголовки, списки, таблицы, формулы).

![01·1](/api/assets/d664…)

<!-- skyfraze: number=01.1 id=… kind=event -->
### 01.1 Сборка на орбитальной верфи
…
```

- Уровень заголовка — по глубине: глава `##`, под-событие `###`, под-шаг `####`.
- Перед каждым событием — машинный комментарий `<!-- skyfraze: number=… id=… kind=event -->`.
  Он не виден в готовом документе, но по нему восстанавливается точная структура.
- Номер кадра тот же, что в приложении: `01`, `01.1`, `01.1.1`; картинки события —
  `01.1·1`, `01.1·2` и идут сразу после текста своего события.
- В обычном экспорте ссылки на картинки абсолютные (`/api/assets/<id>`) — файл
  открывается в браузере и в редакторе с доступом к стенду.

### 1.2. Zip с ассетами: `GET /api/projects/{id}/export.md?assets=1`

```
story.md              вся история одной лентой, ссылки относительные: assets/03-верфь.png
story/                по файлу на событие — это же и есть формат обратного импорта
  01-пролог-представление.md
  01.1-сборка-на-орбитальной-верфи.md
  01.1.1-испытания-корпуса.md
assets/               03-верфь.png, 04-старт.png — номера в именах, чтобы не сталкивались
manifest.json         манифест переноса (формат skyfraze-project, версия 1)
README.txt            что это за архив, в пяти строках
```

Ключевое: `manifest.json` тот же, что в архиве переноса проекта, поэтому **этот zip
годится и для «Импорта проекта» между стендами** — просто внутри него ещё лежит
человекочитаемая версия. Файлы `story.md` и `story/` старый импорт игнорирует.

Архив переноса (`GET /api/projects/{id}/export`) получает те же `story.md` и `story/`,
чтобы обе выгрузки были согласованы.

## 2. Импорт папки: `POST /api/projects/import/markdown[/preview]`

Принимается либо набор `.md`/`.markdown` файлов (multipart, имена — относительные пути,
как их отдаёт браузер для папки: `Глава 01/01-Пролог.md`), либо один zip с такой же
структурой. `preview` ничего не пишет в базу и отдаёт разобранное дерево с
предупреждениями; второй вызов создаёт **новый** проект владельца.

### 2.1. Правила разбора

**Что считается корнем.** Когда папку выбирают в браузере, первым сегментом пути всегда
идёт сама выбранная папка — клиент его срезает, поэтому «выбранная папка = проект», а
главами становятся её подкаталоги. В zip, наоборот, если внутри ровно одна папка
верхнего уровня и в корне нет файлов, её снимает сервер (классическое «zip с одной
папкой»); как только в корне появляются файлы или вторая папка, корень не снимается.
Свой архив выгрузки (`story.md` + `story/`) распознаётся отдельно: сводная лента
событием не становится, папка `story/` снимается.

| Что | Правило |
| --- | --- |
| Уровень | Каталог = уровень вложенности (после снятия корня). Максимум 4 уровня (как `DEFAULT_MAX_DEPTH`); глубже — предупреждение, файл не берём |
| Событие каталога | Каталог становится событием сам: его заголовок и текст берутся из `index.md`, а если такого файла нет — из имени каталога |
| Номер и порядок | Префикс имени: `NN-`, `NN.NN-`, `NN.NN.NN-` (точка в номере допустима). Нет префикса — порядок по имени, номера выдаются подряд |
| Заголовок | front-matter `title:` → первый `# H1` → имя файла без номера и расширения (`-`/`_` → пробелы) |
| Тело | Всё, что осталось. Если заголовок взяли из `# H1`, эта строка из тела убирается (в приложении заголовок показывается отдельно) |
| Front-matter | `title`, `date` (YYYY-MM-DD), `bg`. `bg` принимается, но пока не применяется: настройки фона живут только в CRDT, об этом предупреждаем |
| Прочие файлы | Игнорируются, но в отчёте считается, сколько ссылок на изображения есть в текстах: «картинки не переносятся: N ссылок» |
| Кодировка | UTF-8 (BOM допускается), CRLF нормализуется. Нечитаемый файл — предупреждение, остальные продолжают |
| Лимиты | до 2000 файлов, 4 МБ на файл, 200 МБ суммарно, до 2000 событий |

### 2.2. Безопасность

- zip: отказ при абсолютных путях, `..`, симлинках и управляющих символах в именах
  (zip-slip); распаковка только потоком, без выгрузки всего архива в память;
- имена файлов не используются как пути на диске — только как структура дерева;
- лимиты из таблицы выше проверяются до создания проекта.

### 2.3. Что переносится и что нет

Переносится: заголовок проекта, дерево событий (вложенность, порядок, номера),
заголовки и тексты, дата события.

Не переносится (в этой версии): изображения и другие вложения — ссылки остаются в
тексте как есть; настройки фона кадра.

**Важно про CRDT.** Новый проект не имеет снапшота состояния, и первый открывший
редактор засеивает пустой Y.Doc из таблицы событий, но засев берёт только
`id / parent_id / title / body` (см. `frontend/src/collab/yprovider.ts`). Поэтому:

- импорт заполняет ровно эти поля, и дерево в редакторе появляется корректно;
- `event_date` в базу попадает, но в засев не входит — об этом сообщаем предупреждением;
- импорт в **существующий** проект с непустым снапшотом в этой версии не поддерживается:
  снапшот перезапишет вставленные строки при первом подключении редактора. Это
  отдельная фаза (см. `docs/import-export-folders.md`, п. 5.1).

## 3. Круговой обмен

Обязательное свойство: `export.md?assets=1` → `import/markdown` даёт то же дерево
(номера, заголовки, вложенность, тела). Это проверяется интеграционным тестом на
бэкенде; при изменении правил тест обновляется вместе с ними.

Что **не** едет по кругу в этой версии:

- изображения и вложения — ссылки остаются текстом, файлы не переносятся;
- настройки фона кадра — живут только в CRDT, `bg` из front-matter принимается, но не
  применяется;
- даты событий: импорт читает `date` из front-matter и сохраняет в базу, но выгрузка
  front-matter пока не пишет — то есть дата, поставленная в приложении, в файлах не
  сохраняется. Если понадобится полный круг и по датам, выгрузка начнёт писать
  `--- title: … / date: … ---` в `story/*.md` (место под это в формате уже есть).

Кроме того, в md-zip нет `state.bin`, поэтому в манифесте `has_state=false`: тексты и
вложения переносятся, а фон кадров и CRDT-привязки — только полным архивом
`GET /api/projects/{id}/export`.

## 4. Пример папки, которую можно загрузить

```
01-Пролог.md
01.1-Первая встреча.md
02-Мир/
  index.md
  01-Города.md
  02-Магия.md
assets/            ← пока игнорируется, но имена сохраняются в предупреждении
  карта.png
```

Результат: глава «Пролог» с под-событием «Первая встреча», глава «Мир» (текст из её
`index.md`) с двумя под-событиями.
