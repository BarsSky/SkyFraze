# Живые проверки и диагностика

Скрипты в `frontend/tests/` — это **инструменты на живом стенде**, а не тесты: у большинства
вписан адрес и учётная запись, они создают проекты и кадры, снимают скриншоты и печатают числа
для человека. В CI они не гоняются (там только `npm test`, `go test ./...` и `npm run e2e`) —
CI-наборы описаны в `docs/run.md`, раздел «Тесты».

Зачем они нужны: unit-тесты проверяют правила, e2e — сценарий, а здесь измеряется то, чего не
видит ни один из них, — сколько пикселей в ряду, попадает ли клик в кнопку, что именно шире
экрана, какой элемент перекрыт. Почти каждый появился по конкретному отчёту «не нашёл / слипается
/ обрезается / не работает на телефоне» и остаётся, чтобы тот же дефект не вернулся.

## Как запускать

Почти всем нужны поднятыми:

```bash
# backend на :8181 (см. docs/run.md, «Запуск без Docker») и vite на :5173
cd frontend && npx tsx tests/<скрипт>.ts
```

Общие правила:

* **Проекты убирают за собой сами**: создают проект с уникальным названием и удаляют его в
  `finally`. Если прогон упал посередине — в списке проектов останется «Диагностика …», его можно
  удалить руками.
* **Учётная запись** — `dev.check@example.com` / `hunter22!` (переопределяется `VISUAL_EMAIL`).
  Старые скрипты, которые заводят пользователя сами, требуют `REGISTRATION_MODE=open` и
  `DATABASE_URL` для backend.
* **Снимки** складываются в `_dev_shots/`; часть печатает числовой итог и `проблемы:` — пусто
  значит «дефект не воспроизвёлся».
* **Помощник** нужен для сценариев с `Нестором`: backend с `AI_ENABLED=true` и заглушка
  `node frontend/tests/e2e/stub-ollama.mjs` на `:11490`.
* Адрес стенда переопределяется: `VISUAL_BASE_URL`, `API_URL`, `WIDTH`, `WIDTHS`, `HEIGHT`.

Не путать со юнит-тестами: `tests/basic.test.ts` — единственный файл в `tests/`, который гоняет
`npm test` (остальные здесь — живые скрипты).

Сценарии `scrollytelling.ts`, `public-feed.ts`, `admin-registration.ts` и скилл
`ui-visual-audit` работают при **любом** режиме регистрации: тестовых пользователей они заводят
через заявку с одобрением (`tests/helpers/testUser.ts`). Скрипты `tests/diag-*.ts` старше этого
механизма и регистрируются напрямую через `/register`, поэтому им нужен `REGISTRATION_MODE=open`.

## Аудит панели
