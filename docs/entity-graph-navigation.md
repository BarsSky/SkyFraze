# Граф связей: группы, погружение, поиск по меткам

Разбор вопроса «как сделать, чтобы в отображении сети было видно, кто с кем не связан, как
перебирать группы и группы в группах, как удобно погружаться до конечного звена и как искать по
всем меткам карточек с подсказками». Документ-разбор: сначала что просят и что уже есть, потом как
это решают другие инструменты, потом один конкретный план для SkyFraze с фазами и ценой.

## 1. Что просят

Пять вопросов из отчёта, разложенные по отдельности (у них разные решения, и путать их нельзя):

1. **Карточки с несовпадающими связями** — как их видно в сети? Сейчас в графе они не видны вовсе:
   эго-граф показывает только соседей выбранной карточки, а одиночки живут отдельной строкой
   «вне связей» под холстом.
2. **Перебор групп** — можно ли свайпом листать группы (виды карточек), или нужен другой способ.
3. **Группы в группах** — как показать «Персонажи → Аня и её круг», не потеряв общий вид.
4. **Акцент на главной группе** — первая группа должна быть видна и «весить» больше остальных.
5. **Поиск по индексированным меткам** — искать по всему, чем карточка опознаётся (имя, алиасы, вид,
   подписи связей), выдавать подсказки и по нажатию открывать карточку в обозревателе.

## 2. Что уже есть (по коду, не по памяти)

| Что | Где | Состояние |
|---|---|---|
| Эго-граф | `EntityGraph.tsx` | центр — выбранная карточка, соседи по кругу, «полёт» в центр 320 мс, история назад до 10 шагов |
| Поиск в графе | там же | **только по `entity.name`** через `includes`, до 6 совпадений, клик — перецентровка |
| Карточки без связей | там же | отдельная строка `data-entity-graph-lonely` под холстом; в холст не попадают |
| Узкий/низкий экран | там же | «рейл»: список соседей окном (`RAIL_WINDOW`) с перелистыванием «предыдущие/следующие» |
| Группы карточек | `EntitiesPanel.tsx` (0.97.7) | список карточек разложен по видам, группы сворачиваются; в **графе** групп нет |
| Раскрытая карточка | `EntityGraph.tsx` | карточка узла с видом, алиасами, описанием, ближайшими связями, действиями |
| Матрица, хронология | `RelationsPanel.tsx` | есть и не меняется этим планом |

Отсюда честный ответ на вопрос 2: сейчас **перебирать группы в графе нечем** — группы живут только
в списке карточек под графом, а «рейл» листает не группы, а соседей одной карточки.

## 3. Как это решают другие

**Obsidian, Graph view** — самый близкий по смыслу инструмент (карточки и связи, никакой схемы):

* группы задаются **поисковым выражением и цветом** (New group → запрос → цвет), то есть группа —
  это сохранённый фильтр, а не отдельная сущность;
* «Local graph» показывает не весь граф, а окружение активной заметки и имеет **слайдер глубины**:
  каждый уровень добавляет связи предыдущего — это ровно «погружение до конечного звена»;
* размер узла = сколько ссылок на него, «Orphans» — переключатель показа одиноких карточек;
  клик по узлу открывает заметку.
  Источник: [Graph view — Obsidian Help](https://raw.githubusercontent.com/obsidianmd/obsidian-help/master/en/Plugins/Graph%20view.md).

**Kumu, кластеризация** — как делать «группы в группах» без новой модели данных: включаете кластер по
полю, и инструмент создаёт **элементы-кластеры** и рёбра к ним; правил можно добавить несколько
(«люди по организациям», затем «организации по секторам») — это и есть вложенность.
Источник: [Cluster — Kumu docs](https://docs.kumu.io/guides/clustering.md).

**Neo4j Bloom** — поиск как построение запроса: подсказки строятся из **словаря схемы** (метки,
категории, типы связей, значения свойств), значения свойств ищутся **по индексам**, а не полным
перебором; подсказки уточняются по мере набора. Это прямой образец для «подсказок из
проиндексированных метк» из вопроса 5.
Источник: [Graph pattern search — Neo4j Bloom](https://neo4j.com/docs/bloom-user-guide/2.15/bloom-tutorial/graph-pattern-search/).

**Семантический зум и focus+context** — академическая линия: при увеличении меняется не только
масштаб, но и **что именно показано** (узел → подпись → детали), а «рыбий глаз»/линза дают крупный
фокус, не теряя контекста. Красиво, но это отдельный движок раскладки и тяжёлая анимация; на
телефоне почти всегда проигрывает списку.
Источники: [семантический зум, рис. 3.12](https://pure.mpg.de/pubman/item/item_1752950_8/component/file_1752949/3-8440-1275-3_DOK.PDF),
[обзор искажений focus+context](https://theses.hal.science/file/index/docid/113852/filename/These_BOUTIN_Francois.pdf),
[«разворачивание» с сохранением pan/zoom](https://uclab.fh-potsdam.de/wp/wp-content/uploads/bludau2023_unfolding.pdf).

## 4. Вывод: три семьи решений, а не одна

| Подход | Что даёт | Чем платим | Брать? |
|---|---|---|---|
| **A. Семантический зум** (один холст, вид зависит от масштаба) | один взгляд на весь мир, красиво | свой движок раскладки, тяжёлые анимации, на телефоне не читается | нет |
| **B. Погружение с крошками** (экран = один уровень: группы → карточки → связи; свайп/стрелки между группами, крошки сверху) | понятно, дешево, работает пальцем | теряется контекст соседних групп | **да, основа** |
| **C. Расширение по глубине** (от карточки: соседи → соседи соседей, слайдер 1–3) | лучший ответ на «кто связан с кем» | не про группы | **да, внутри B** |

Рекомендация: **B отвечает за навигацию, C — за глубину, A не берём** (только «семантику подписей»
— на дальнем масштабе прячем подписи рёбер, это дёшево и полезно).

## 5. План для SkyFraze

### 5.1. Уровни и что на них видно

```
Мир проекта            →  группы-виды: «Персонажи · 12», «Места · 5», «Свои типы»
   ↓ клик по группе / свайп ←→
Группа (вид)           →  карточки этого вида; акцент на главной группе
   ↓ клик по карточке
Карточка (эго-граф)    →  соседи по кругу (это уже есть)
   ↓ «глубже»
Глубина 2–3            →  соседи соседей, слайдер глубины 1–3
```

* **Акцент на главной группе.** Главная — та, что первая в порядке видов проекта (`types.position`),
  то есть «Персонажи» по умолчанию. Акцент — размер и насыщенность узла-группы (как размер по
  числу ссылок в Obsidian) и подпись под ним: «12 карточек · 30 связей»; остальные группы — мельче,
  но с числом карточек, чтобы видно было, что в них есть.
* **Группы в группах.** Второй уровень вложенности не выдумываем: подгруппа — это **подпись связи**
  («живёт на», «боится», «нашла письмо от»), сгруппированная как кластер (Kumu-приём). Внутри
  «Персонажей» видно: Аня — живёт на → Земля, боится → Сторож; «Земля» — принадлежит → …, и т. д.
  Это отвечает на «группы в группах» без новой сущности и без ручной раскладки.
* **Карточки без связей** (вопрос 1). Правило: одиночки **не прячем и не смешиваем** с сетью.
  В группе они стоят отдельной свёрнутой полкой «вне связей · 3» с раскрытием; в мире — в счётчике
  группы («Персонажи · 12, из них 2 без связей»). Так видно и то, что связь потеряна, и то, что
  карточек не потеряли.
* **Перебор групп** (вопрос 2): на телефоне — **свайп** по холсту влево/вправо (одна группа на
  экран, как карусель), на десктопе — стрелки ← → и клик по крошке; клавиатура — `[` и `]`. Тот же
  жест уже есть в полноэкранном просмотре картинок — язык не новый.
* **Крошки** сверху холста: «Мир / Персонажи / Аня». Клик по «Мир» — назад к группам, клик по
  «Персонажи» — в группу, всё с тем же «полётом» 320 мс (механизм у нас уже работает).
* **Погружение до конечного звена** (вопрос про «эффект развертывания»): два движения, оба уже
  наполовину есть — «полёт» выбранной карточки в центр (0.84.0) и слайдер глубины 1–3. У конечного
  звена (карточка без соседей) показываем честно: «связей нет — вот с чего начать», а не пустой
  холст.

### 5.2. Поиск по меткам (вопрос 5)

Индексируемые метки — **имя, все алиасы, вид, подписи связей**. Индекс строится один раз на
проект (`Map` нормализованная строка → карточка), потому что иначе поиск по 30 карточкам и по 300
карточкам — это два разных по скорости поведения.

* Подсказки под полем: до 8 строк вида «**Аня** · Персонаж · еще «Анна», «Аня Ветрова»» с подсветкой
  совпадения; группы результатов по виду, чтобы «дом» не путался с «Домом на холме».
* Навигация с клавиатуры (↑↓, Enter) и пальцем; Esc закрывает.
* По нажатию карточка **открывается в обозревателе** (карточка узла с видом, алиасами, описанием,
  связями и действиями) — не уводя с графа: граф остаётся контекстом, обозреватель показывает
  детали. Если человек ищет в глубине группы, крошки сохраняются.
* Пустой результат — не «ничего не найдено», а подсказка: «по „ан“ ничего нет; добавить алиас?» —
  это ровно тот случай, когда связь есть в тексте, но ищется не по той форме.

### 5.3. Что не делаем

* семантический зум геометрии, 3D, «рыбий глаз» — на телефоне не читается, а движок раскладки
  тянет за собой тесты и производительность;
* ручные «мировые» группы помимо видов: виды уже есть в данных, вторая система группировки
  разошлась бы с первой;
* отдельную страницу «карта мира» — граф и так на вкладке «Связи».

## 6. Фазы и цена

| Фаза | Что | Оценка | Состояние |
|---|---|---|---|
| 1 | поиск по индексу меток (имя + алиасы + вид + подписи связей) с подсказками и открытием в обозревателе | 2–3 ч | **сделано** (0.100.0): `lib/entitySearch.ts`, подсказки объясняют, почему карточка в выдаче |
| 2 | уровень «мир» с группами и акцентом на главной; вход в группу; стрелки/свайп; «глубже» с уровнями окрестности | 4–6 ч | **сделано** (0.100.0): `collab/neighborhood.ts`, крошки «Мир / Группа», свайп и стрелки |
| 3 | подгруппы по подписям связи внутри группы (свернуть/развернуть), «группы в группах»; запоминание уровня в localStorage | 6–8 ч | **сделано** (0.101.0): egraph__cluster, lib/graphView.ts |

**Что именно сделано в 0.100.0** (по ответам из отчёта):

* **главная группа — созданная первой**: порядок групп задаёт `created_at` вида, `position` остаётся
  запасным ключом для старых данных; главная получает акцентную рамку и полосу;
* **«глубже» без верхней границы**: уровни окрестности считает обход в ширину и останавливается,
  когда новых карточек нет — не по числу, а по данным; кнопка «ещё уровень» показывается, только
  когда глубже действительно что-то есть;
* **свайп — пробный**: жест работает на списке карточек группы (влево/вправо), рядом стрелки «←/→»;
  если на телефоне окажется, что он мешает, его убирает одна строка, а навигация остаётся;
* **подгруппа — подпись связи** (0.101.0): внутри группы карточки разложены по подписям («живёт на
  · 2», «боится · 1»), каждая подгруппа сворачивается, карточки без связей — в подгруппе «вне
  связей». Одна карточка может стоять в нескольких подгруппах: это не папка, а отношение (у Ани есть
  и «живёт на», и «боится»);
* **уровень запоминается на проект** (0.101.0, `skyfraze-graph-view:<id>`): человек, который смотрит
  мир по группам, возвращается туда же. Карточка в центре не запоминается — «какая карточка была
  открыта неделю назад» полезным состоянием не является. Запись делается **явно в действиях** (клик
  по группе, крошке, карточке), а не эффектом на любое изменение: в dev-режиме компонент
  монтируется дважды, и эффект записи успевал записать уровень по умолчанию раньше, чем второй
  монтаж читал сохранённое (ловилось живой проверкой).

## 7. Решения из отчёта (ответы получены)

1. **Главная группа** — та, что создана первой (не по порядку `position` и не по размеру).
2. **Подгруппа** — подпись связи (как предложено, без ручных групп).
3. **Свайп** — сначала испробовать; сейчас сделан пробно, решение после пробы на телефоне.
4. **Глубина** — без верхней границы.
