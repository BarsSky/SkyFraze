# История версий проекта: что снимается, когда и как восстановить

Коротко: **у проекта теперь есть история, а не только текущее состояние.** Версии снимаются
сами по ходу правок и по кнопке «Сохранить версию», а восстановление возвращает содержимое
проекта на выбранный момент — одной кнопкой, из интерфейса.

Зачем это, если есть резервные копии (`docs/backups.md`): копия — снимок **всей машины раз
в сутки**, и достать из неё один проект, чтобы отменить одну неудачную правку, — это
развернуть дамп в отдельную базу и перетащить проект руками. История версий решает ровно
противоположную задачу: мелко, часто и про один проект.

## 1. Что такое версия

Версия — снапшот CRDT-документа проекта целиком (тот же формат, что в
`project_event_state`): кадры, их тексты, заголовки, даты, порядок, вложения и фон. Не
диффы: диффы меньше, но порванная цепочка (например, если сработало удержание) делает
бесполезными все последующие версии.

Таблица `project_revisions` (миграция 0016): `yjs_state`, `events` (сколько кадров),
`checksum`, `kind` (`auto` | `manual`), `label`, `created_by`, `created_at`, размер.

## 2. Когда версия снимается

| Вид | Когда | Как часто |
| --- | --- | --- |
| `auto` | сервер, после сохранения снапшота живой комнаты | не чаще `VERSIONS_INTERVAL_MINUTES` (по умолчанию 5 минут) **и** только если содержимое изменилось (сверка контрольной суммы) |
| `manual` | человек нажал «Сохранить версию» в окне «Версии» | всегда, без троттлинга; можно дать подпись |

Троттлинг нужен с двух сторон: снимать версию на каждое нажатие клавиши — это лента
нажатий вместо истории, а «раз в сутки» уже покрыто бэкапами. Пять минут — компромисс:
человек не пишет быстрее, чем успевает захотеть «верни как было пять минут назад».

## 3. Сколько хранится

Удержание считается при каждой вставке версии:

- `VERSIONS_KEEP` (по умолчанию 100) — сколько версий на проект;
- `VERSIONS_MAX_MB` (по умолчанию 32) — предел суммы снапшотов на проект.

Удаляются **самые старые** версии. Ориентир по объёму: снапшот большого проекта (каталог
промптов со стенда, 58 кадров) — около 361 КБ, то есть 100 версий ≈ 36 МБ, а предел в
32 МиБ срабатывает раньше и держит историю в разумных рамках.

## 4. Как восстановить

Окно **«Версии»** на стадии проекта (кнопка рядом с «Редакторы»):

1. «Показать» — предпросмотр: что было в версии (дерево кадров, даты, знаки). Восстановление
   без предпросмотра — это нажатие вслепую, поэтому его нет.
2. «Восстановить» → «Точно восстановить?» (второе нажатие подтверждает: первое уже спрашивает, но не меняет).
3. После восстановления окно пишет, что изменилось: сколько кадров вернулось, переписано,
   переставлено и удалено.

**Восстановление — это обычная правка, а не подмена файла.** В Yjs нельзя заменить документ:
клиент с более новыми правками пришлёт их обратно при следующем подключении, и
восстановление отменилось бы само. Поэтому сервер приводит документ к состоянию версии
операциями (удаление лишнего, перезапись полей, возврат пропавшего, восстановление порядка)
— одной транзакцией. Из этого следует:

- открытые вкладки видят восстановление сразу, без перезагрузки;
- это **не откат часов**: содержимое совпадёт с версией, а записи «кто и когда правил»
  останутся новыми (кадры будут выглядеть так, будто их только что изменили);
- восстановление само становится новым состоянием — и через пять минут попадёт в историю
  как новая версия, то есть отменить восстановление тоже можно.

Что восстанавливается: кадры, заголовки, тексты, даты, порядок, родители, вложения, фон
(`bg_kind` + `bg_asset`/`bg_tone`) и `created_at` кадра. Чего в версии нет вовсе: прав
доступа, вложений как файлов (они живут отдельно; удалённый файл версия не вернёт),
настроек проекта и истории бесед с помощником.

## 5. API

```
GET    /api/projects/{id}/versions?limit=50        версии проекта (viewer+)
POST   /api/projects/{id}/versions                 ручная версия {label} → 201 (editor+)
GET    /api/projects/{id}/versions/{vid}           дерево версии: кадры, даты, знаки (viewer+)
POST   /api/projects/{id}/versions/{vid}/restore   привести проект к версии (editor+) →
                                                   {removed, added, updated, moved, warning}
DELETE /api/projects/{id}/versions/{vid}           удалить версию (editor+)
```

```sql
project_revisions (id, project_id, yjs_state bytea, events int, checksum text,
                   kind auto|manual, label text, created_by uuid, created_at timestamptz)
```

## 6. Ограничения, о которых стоит знать

- **Не история каждого нажатия.** Между версиями — до пяти минут правок; в пределах этого
  окна восстанавливать нечего. Если нужна точка отсчёта («вот так было хорошо») — «Сохранить
  версию» с подписью.
- **Восстановление не удаляет историю версий.** Оно возвращает проект, а не отматывает
  историю: все версии остаются на месте, и можно вернуться к любой другой.
- **Удалённый файл вложения не возвращается**: версия хранит идентификаторы вложений, а сами
  файлы живут в хранилище проекта (`docs/storage-compression.md`).
- **Права.** Читать историю может любой участник проекта; восстанавливать, сохранять и
  удалять версии — только editor и владелец. Читатель видит список и предпросмотр без кнопок.
