# Как присылать изменения

Спасибо, что дошли до этого файла. SkyFraze — открытая платформа (Apache-2.0), и вклады
приветствуются: исправления, новые возможности, документация, переводы.

English version: [CONTRIBUTING.en.md](CONTRIBUTING.en.md).

## Лицензия вкладов

* Вклады принимаются **на условиях Apache-2.0** (inbound = outbound): присылая изменение, вы
  разрешаете распространять его под лицензией проекта.
* **Проект не планирует менять лицензию** и не выпускает платную или закрытую редакцию. CLA нет и
  не предполагается — от вас не требуется передавать исключительные права.
* Подписывайте коммиты `-s` (Developer Certificate of Origin): `git commit -s -m "…"`. Этим вы
  подтверждаете, что вправе отдать код под этой лицензией.
* Присылая вклад, вы соглашаетесь, что он может быть использован в проекте бессрочно и без
  вознаграждения.

Происхождение проекта и как проверяется авторство — [PROVENANCE.md](PROVENANCE.md).

## Что приветствуется

* исправления ошибок — с тестом, который падал до правки;
* новые возможности — с описанием задачи (что и зачем), тестами и записью в `CHANGELOG.md`;
* документация и переводы — особенно на английский: интерфейс сейчас русский, но публичные
  документы должны быть на двух языках;
* сообщения об ошибках — с шагами воспроизведения; если дело в вёрстке, приложите ширину экрана и
  скриншот (аудит интерфейса проверяет именно это).

## Перед pull request

1. **Поднимите стенд** — `docker compose up --build -d` (быстрый старт в [README.md](README.md)),
   либо dev-режим и переменные окружения по [docs/run.md](docs/run.md).
2. **Прогоните проверки:**
   ```bash
   cd backend  && go vet ./... && go test ./...
   cd frontend && npm run lint && npm test
   cd frontend && npm run e2e          # нужна ПУСТАЯ база, см. docs/run.md
   ```
3. **Опишите изменение в `CHANGELOG.md`** — формат Keep a Changelog, версия в заголовке.
4. **Не добавляйте секретов** — ни `.env`, ни ключей, ни токенов. Файлы стенда в `.gitignore`.
5. **Новые зависимости — с обоснованием** и только с разрешительной лицензией (MIT, BSD,
   Apache-2.0). Копилефт в рантайме продукта требует отдельного решения: правило и текущий состав —
   [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md).

## Стиль коммитов

```
тип(область): краткое описание в повелительном наклонении
```

`тип` — `feat`, `fix`, `docs`, `test`, `chore`, `refactor`, `perf`. Описание — по-русски или
по-английски, одна строка до 72 символов. Тело — «почему», а не «что»: что изменилось, видно в
diff. Одному изменению — один коммит; в проекте не принято «свалить всё в один».

## Как устроен код

Коротко: `backend/` — Go (chi, pgx, Yjs-релей), `frontend/` — React + TypeScript + Vite,
`docs/` — разборы решений: что просили, почему сделано так, что проверено. Полное дерево —
[docs/run.md](docs/run.md), модель данных и инварианты — [docs/architecture.md](docs/architecture.md).

Стиль: существующий код читается как есть — отступы, кавычки и именование берутся из соседних
файлов, а не из внешнего гайда. Комментарии объясняют **почему** так, а не что делает строка.

## Форки и свои установки

Разворачивайте, меняйте, ведите свои проекты со своей командой — лицензия это разрешает и проект
именно для этого: контент, созданный в вашей установке, ваш и лицензией на ПО не покрывается.
Если раздаёте сборку — сохраните `LICENSE` и `NOTICE` и не используйте название и логотип
SkyFraze как свои (Apache-2.0, §4 и §6).

## Поведение

Обсуждайте идеи и код, а не людей. Оскорбления, травля и дискриминация — причина для отказа в
любом вкладе без обсуждения.

## Куда писать

* ошибки и предложения — issues репозитория;
* уязвимости — **не** в issues: опишите приватно владельцу (контакт в профиле
  <https://github.com/BarsSky>) и дайте время на исправление до публикации.
