# ui-visual-audit

Проверяет **то, что видит человек**, и **то, что заявлено в README**, на живом стенде.
Находит дефекты восприятия числами (геометрия, переполнение, контраст, hit-test),
а не «на глаз», и подсказывает, какой файл править.

## Когда применять

- Панель выглядит неправильно: текст обрезан/наплывает, элемент «съехал», картинок нет.
- Кнопка или поле не реагируют на клик.
- Нужно убедиться, что все заявленные возможности проекта действительно работают.
- Перед демонстрацией или после визуальной правки.

## Порядок работы

1. **Стенд должен быть поднят.** `docker compose up -d` (frontend :80, backend, postgres).
   Если что-то пересобиралось — проверь, что браузер не держит старый бандл:
   `curl -sD - -o NUL http://localhost/index.html | grep -i cache-control` → должен быть `no-store`.
2. **Запусти раннер** (Playwright уже есть во фронтенде):

   ```bash
   cd frontend
   npx tsx ../.dsh/skills/ui-visual-audit/scripts/visual-audit.ts            # всё
   ONLY_SCREENS=1 npx tsx ../.dsh/skills/ui-visual-audit/scripts/visual-audit.ts   # только визуал
   ONLY_FUNCTIONAL=1 npx tsx ../.dsh/skills/ui-visual-audit/scripts/visual-audit.ts # только функции
   ```
   Отчёт: `_audit_out/visual-report.md`, `_audit_out/visual-report.json`, скриншоты рядом.
3. **Читай отчёт сверху вниз** — находки отсортированы по важности:
   `error` (видно сломанное) → `warning` (мешает восприятию) → `info` (мелочи).
   Для каждой находки указан селектор/экран/вьюпорт — правь тот файл, что в колонке `where`.
   В `info` попадают и **маркеры покрытия** («текст не обрезан», «всё внутри вьюпорта»,
   «нет текста мельче 12px» и т.п.): если по какому-то классу проверок нет ни находки,
   ни маркера, значит этот класс не выполнялся.
4. **Правь и перезапускай** до нуля `error`. Дальше — warnings, если они заметны глазом.
5. **Закрепи регрессию** в `frontend/tests/scrollytelling.ts` или в самом раннере:
   проверка, которую нашли один раз, должна остаться в наборе.

## Что проверяется (визуал)

| Проверка | Что означает |
|---|---|
| `overflow-x` у текстовых узлов | текст шире контейнера → обрезан или вылезает |
| элемент вне вьюпорта (X/Y) | «съехало»: элемент не влезает в экран |
| пересечение интерактивных элементов | один control перекрывает другой (частая причина «не нажимается») |
| `hit-test` в центре контроля | клик попадает не в тот элемент (fixed-слой стадии, z-index) |
| цель нажатия < 32px (моб.) | слишком мелкая кнопка |
| картинка не загружена (`naturalWidth === 0`) | 401/404 у ассета или битый файл |
| контраст текста < 3.5 | нечитаемо на фоне |
| горизонтальный скролл документа | макет шире экрана |
| fixed-слой поверх контента в `idle` | стадия крадёт клики у редакторов |
| шрифт < 12px, кегль заголовков вне шкалы | мелочи восприятия |
| console errors / HTTP ≥ 400 | сеть и рантайм |
| ошибка показана сырым текстом (`TimeoutError…`) | нет плашки с выходами — см. `ErrorBanner` |

Экраны: `login`, `projects`, таймлайн (все кадры + все темы + все вьюпорты), редакторы,
`settings`, `admin` (админка развёртывания), `feed` (лента), `story` (публичная история).
Публичные страницы проверяются ещё и **глазами анонима** — в отдельном контексте без
входа: они должны открываться без авторизации и не содержать ни одного элемента правки.
Скриншоты каждой позиции — в отчёте.

## Что проверяется (функции)

Матрица «заявлено в README → проверено»: регистрация/логин, создание проекта,
глава → под-событие → внук, сквозная навигация кадров, тема, загрузка файла
(малый и >1 МБ), прикрепление и галерея с просмотром, фон кадра (тон/картинка),
сохранение после перезагрузки, приглашение с ролью (viewer не пишет, editor пишет),
realtime CRDT (две вкладки видят правки друг друга), публичная лента: в ленте только
опубликованное, публичная страница открывается анонимом и не содержит правок, аноним
получает 401 на оценку, автор — 403 на самооценку, голос читателя учитывается, звёзды
вне 1..5 отклоняются, повторный заход не накручивает просмотры, снятие с публикации
скрывает историю (404) и повторная публикация сохраняет ссылку.

Администрирование: `GET /api/auth/config` отдаёт режим, в режиме «по заявке» прямая
регистрация закрыта (403), заявка принимается (202), вход до решения даёт 403,
администратор видит заявку и одобряет её, одобренный входит тем же паролем и получает
403 на `/api/admin/*`, а переключение режима в `open` открывает регистрацию.

Перенос проекта: `GET /api/projects/{id}/export` отдаёт ZIP (проверяется сигнатура PK и
непустой размер), а повторная загрузка того же архива в ту же базу обязана получить 409 —
молча «перезаписать» проект нельзя. Полный сценарий переноса (экспорт из интерфейса →
удаление источника → импорт → проверка глав, вложенности и файлов) — в
`frontend/tests/project-transfer.ts`, перенос между двумя стендами — в
`frontend/tests/cross-host-transfer.ts`.

Аудит **сам публикует демо-проект** (`POST /api/projects/{id}/publication`): без этого
публичных экранов просто не существует. В конце демо-проект остаётся опубликованным —
он витрина проекта. Свои тестовые проекты аудит создаёт и удаляет сам.

### Тестовые пользователи и режим регистрации

Аудит работает на любой инсталляции: `ensureTestUser()` сначала пробует прямую
регистрацию, а при 403 (режим «по заявке») подаёт заявку и одобряет её админским
токеном. Поэтому проверки ролей и оценок не зависят от того, открыта регистрация
или нет.

Тестовые пользователи (`audit.*@e.com`, приглашённые) **остаются** в базе: удаления
пользователей в API нет, а создавать его ради уборки — лишняя поверхность атаки.
Их видно в админке в списке пользователей; при необходимости чистить вручную SQL-ом.

## Частые причины дефектов (проверено на этом проекте)

- **Fixed-слой стадии перехватывает клики** → стадия должна уходить в `data-stage="idle"`
  и получать `visibility: hidden`, а не только `opacity: 0`.
- **Ассеты отдаются только с авторизацией** → `<img src="/api/assets/{id}">` даёт 401;
  файлы надо тянуть через `src/api/assetObject.ts` (blob-URL), иначе картинок нет нигде.
- **`client_max_body_size` в nginx** (по умолчанию 1 МБ) → любая фотография даёт 413,
  «файлы не добавляются».
- **`index.html` без `Cache-Control: no-store`** → после пересборки браузер держит
  старый бандл, и «ничего не работает».
- **Текст внутри SVG-иллюстрации** обрезается из-за `preserveAspectRatio="slice"` →
  подписи держать в DOM, а не в картинке.
- **Колонка копирайта** должна ограничивать высоту и скроллить текст, иначе на
  длинных описаниях панель вылезает за экран.
- **`html { font-size: 14px }` и rem-размеры** → любой `0.8rem` превращается в 11px:
  подписи навигации «мелкие и неудобные». Либо база 16px, либо px в мелких подписях.
- **Подписи, всплывающие только по hover** (навигация по главам) → названия не читаются,
  пока не наведёшь; навигация должна показывать подписи постоянно и переносить длинные
  строки (2 строки + `title`), а не обрезать их многоточием в узкой колонке.
- **Проверяй фактический кегль, а не исходник**: `getComputedStyle(el).fontSize` —
  значение `rem` зависит от корня, поэтому в CSS «0.9rem» может оказаться 12px.
- **Ссылки-«текст» без `min-height`** («Читать →», публичная ссылка проекта,
  сортировки ленты) на телефоне дают цель нажатия ~20–31px: либо оборачивать в кнопку,
  либо `inline-flex; min-height: 34px` в мобильном медиа-запросе.
- **Публичные страницы проверяй без авторизации.** Вход в аудите маскирует дефект:
  страница может «работать» только потому, что в контексте лежит токен (ассеты, лента,
  пустое состояние). Отдельный контекст без localStorage ловит это сразу.
- **Картинка в полёте — не битая картинка.** Проверка `img.complete === false` даёт
  ложные срабатывания на обложках и `loading="lazy"`; раннер сначала ждёт загрузку
  (короткий таймаут, не `networkidle` — со WebSocket он не наступает), а битой считает
  только `complete && naturalWidth === 0` у картинки в пределах экрана.
- **Серверный `fetch` без cookie — всегда «новый посетитель».** Проверять дедупликацию
  просмотров надо через интерфейс (открыть страницу, перезагрузить, сравнить счётчик),
  иначе проверка накручивает то, что измеряет.

## Границы

- Скилл не меняет данные пользователя: тестовые проекты создаёт и удаляет сам.
- Контраст считается по ближайшему непрозрачному фону; над фото/градиентом помечается
  как непроверяемый, а не как ошибка.
- Скилл проверяет восприятие и функциональность, но не вкус: композиция/стиль
  оцениваются по `deps/scroll-world/skills/scroll-world/references/index-template.html`.
